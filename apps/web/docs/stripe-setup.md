# Stripe Setup Guide

Steps to configure the Stripe Dashboard so that the Blindfold Chess paid plan
($1/month ad-free) works correctly.

## Prerequisites

- [Stripe account](https://dashboard.stripe.com/register)
- Stripe CLI (for local development): `brew install stripe/stripe-cli/stripe`

## 1. Obtaining API Keys

### Test Environment

1. [Stripe Dashboard](https://dashboard.stripe.com/test/apikeys) > Developers > API keys
2. Copy the following keys:
   - **Secret key** (`sk_test_...`) → `STRIPE_SECRET_KEY` in `.env.local`
   - Publishable key is not needed (not used with the Checkout redirect approach)

### Production Environment

1. [Stripe Dashboard](https://dashboard.stripe.com/apikeys) > Developers > API keys
2. Secret key (`sk_live_...`) → `STRIPE_SECRET_KEY` in Vercel environment variables

## 2. Creating a Product & Price

### Test Environment

1. [Stripe Dashboard](https://dashboard.stripe.com/test/products) > Products > + Add product
2. Configure the following:
   - **Name**: `Ad-Free Plan` (or any name you prefer)
   - **Description**: `Remove all advertisements from Blindfold Chess` (optional)
3. Pricing:
   - **Pricing model**: Standard pricing
   - **Price**: `$1.00`
   - **Billing period**: `Monthly`
   - **Currency**: `USD`
4. Save product
5. Copy the created Price ID (`price_...`) → `STRIPE_PRICE_ID` in `.env.local`

### Production Environment

Follow the same steps in live mode. The Price ID will be different,
so set the production `STRIPE_PRICE_ID` in Vercel environment variables.

> **Note**: The Price ID differs between test and production environments.
> Make sure to set the correct value for each environment.

## 3. Webhook Configuration

### Local Development (Stripe CLI)

```bash
# Log in to Stripe CLI
stripe login

# Forward webhooks to localhost
stripe listen --forward-to localhost:3000/api/stripe/webhook

# Copy the webhook signing secret (whsec_...) from the output
# → STRIPE_WEBHOOK_SECRET in .env.local
```

The Stripe CLI only forwards webhooks while it is running.
Keep it running in a separate terminal during development.

### Sending Test Events

```bash
# Simulate a checkout completion event
stripe trigger checkout.session.completed

# Subscription update event
stripe trigger customer.subscription.updated

# Subscription deletion event
stripe trigger customer.subscription.deleted
```

### Production Environment (Stripe Dashboard)

1. [Stripe Dashboard](https://dashboard.stripe.com/webhooks) > Developers > Webhooks
2. Click **+ Add endpoint**
3. Configure the following:
   - **Endpoint URL**: `https://www.blindfold-chess.online/api/stripe/webhook`
   - **Events to send**:
     - `checkout.session.completed`
     - `customer.subscription.updated`
     - `customer.subscription.deleted`
4. Save with **Add endpoint**
5. Copy the **Signing secret** (`whsec_...`) from the endpoint details page
   → `STRIPE_WEBHOOK_SECRET` in Vercel environment variables

> **Important**: The webhook secrets for production and local are different.
> Use the secret generated by the Stripe CLI locally, and the secret from the Dashboard in production.

## 4. Customer Portal Configuration

1. [Stripe Dashboard](https://dashboard.stripe.com/test/settings/billing/portal) > Settings > Billing > Customer portal
2. Configure the following:

### Business information

- **Privacy policy**: `https://www.blindfold-chess.online/en/privacy`
- **Terms of service**: `https://www.blindfold-chess.online/en/terms`

### Subscriptions > Cancellations

- **Cancel subscriptions**: Enabled
- **Cancellation reason**: Enabled (optional; collects cancellation reasons)
- **Proration behavior**: `None` (no proration needed for $1/month)

### Subscriptions > Subscription updates

- **Switching plans**: Disabled (only a single plan at this time)
- **Plan quantities**: Disabled

### Payment methods

- **Update payment methods**: Enabled

### Invoices

- **Invoice history**: Enabled

3. **Save changes**

## 5. Environment Variables Summary

### Local Development (`.env.local`)

```env
STRIPE_SECRET_KEY=sk_test_XXXXXXXXXXXXXXXXXXXX
STRIPE_WEBHOOK_SECRET=whsec_XXXXXXXXXXXXXXXXXXXX  # Value from Stripe CLI output
STRIPE_PRICE_ID=price_XXXXXXXXXXXXXXXXXXXX         # Test environment Price ID
```

### Production (Vercel Environment Variables)

```
STRIPE_SECRET_KEY=sk_live_XXXXXXXXXXXXXXXXXXXX
STRIPE_WEBHOOK_SECRET=whsec_XXXXXXXXXXXXXXXXXXXX  # Signing secret from Dashboard Webhook
STRIPE_PRICE_ID=price_XXXXXXXXXXXXXXXXXXXX         # Production environment Price ID
```

> **Security**: Never add the `NEXT_PUBLIC_` prefix to `STRIPE_SECRET_KEY`.
> It must only be used on the server side.

## Troubleshooting

### Webhook Signature Verification Error

```
Webhook signature verification failed
```

- Verify that `STRIPE_WEBHOOK_SECRET` in `.env.local` matches the value from the `stripe listen` output
- In production, use the Signing secret from the Webhook endpoint details in the Dashboard
- Local and production secrets are different

### Checkout Session Creation Error

- Verify that `STRIPE_PRICE_ID` is the correct value for the environment (test/production)
- Test environment Price IDs start with `price_xxx`, and production IDs are similar but have different values

### Customer Portal Not Displaying

- Verify that the Customer Portal is enabled in the Stripe Dashboard
- Verify that the settings are saved under Settings > Billing > Customer portal
